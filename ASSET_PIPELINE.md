# Asset pipeline

All assets are original. Nothing is extracted from or traced over any other game.

## Textures
- **Size:** standard block and item textures are 16×16 PNG (RGBA8). The packer rejects any other
  size unless the file is listed under `exceptions` in `assets/textures/manifest.json` with a
  reason. Expected exceptions: entity skins, GUI, fonts.
- **Style:** small per-material palettes (4–6 shades), no anti-aliasing, alpha that is either
  fully opaque or fully transparent except on translucent materials.
- **Sampling:** nearest-neighbour everywhere, and mipmaps are generated with alpha-coverage
  preservation for cutout blocks.
- **Generation:** `tools/gen_textures.py` draws every texture procedurally (noise fills, boards,
  rings, specks, outlines) from per-material palettes. Existing PNGs are kept unless `--force` is
  passed, so hand edits survive.
- **Packing:** `tools/build_assets.py` validates dimensions, finds textures that are referenced
  but missing (and the reverse), deduplicates identical images by content hash, and builds a
  2D texture array plus `assets/generated/voxcraft.pak` (manifest + data, LZ4). It rebuilds
  incrementally by source hash.
- **Tint:** turf, leaves and water are stored greyscale and tinted per biome at mesh time.
  One texture serves every biome.

## Models (OpenSCAD)
- Editable sources live in `assets/models/*.scad`. They use a shared `lib.scad` of parametric
  modules, with 1 unit = 1 pixel (16 = one block) and the origin at the block's bottom-north-west
  corner.
- `tools/scad_export.py` finds OpenSCAD (`PATH`, `/opt/homebrew/bin`, `/Applications/OpenSCAD.app`,
  `%ProgramFiles%\OpenSCAD`), exports STL/3MF and validates manifold output. It then converts to
  the runtime format: boxes with per-face UV rectangles. Most voxel models are boxes, so a
  box list is smaller and faster than triangle soup.
- Ordinary full cubes never go through OpenSCAD. They are generated by the mesher.

## Animation
- Models are bone hierarchies of boxes. Clips are keyframed rotation/translation per bone, with
  linear or step interpolation, stored as JSON and packed.
- Procedural layers (walk cycle from speed, head look) are blended on top in code. Distant
  entities update at reduced rates.
- Sign convention: models face -Z. A positive X angle swings a hanging limb forward and tilts a
  head up. A negative X angle lowers a head or leans a body forward. A test pins this.
- The player rig (`"player"` in `animations.json`) adds eased stance layers to the shared
  locomotion: sneak lean (legs stay vertical), swim (body flat), climb (hand over hand),
  airborne arms, and a raised arm while using an item.
- Box faces sample the top-left of their 16×16 tile: an 8×8 head uses pixels 0..7, and a
  4×12 limb uses rows 0..11. Skins that are not uniform (faces, belts, boots) put their detail
  there.

## OpenSCAD workflow
1. Edit `assets/models/src/<name>.scad`. Build it from `vx_bone(name, parent, pivot)` and
   `vx_box(bone, min, size, tex, front)` in `lib.scad`.
2. Run `python3 tools/scad_export.py`. For each model it:
   - locates OpenSCAD (PATH, Homebrew, OpenSCAD.app, Program Files),
   - renders the model to STL to prove the geometry builds,
   - parses the echoed bone and box records,
   - validates the hierarchy,
   - writes `assets/models/built/<name>.json`, stamped with the source hash. It only rewrites
     what changed.
3. The built JSON is committed, so builds and CI never need OpenSCAD. `build_assets.py` warns if
   a built model is stale (`scad_export.py --check`) and merges the models into
   `assets/generated/models.json`.
